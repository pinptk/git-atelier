# Gitキャンプ

ブランチとコミットをクリックして、Gitの動きを視覚的に学べる日本語シミュレーターです。

## 開き方

**`git-atelier.html` をダブルクリックして、Edge / Chrome などのブラウザで開いてください。**

このファイルだけで動作します。インストール、サーバー、ネット接続は不要です。PCとスマートフォンに対応し、画面幅に合わせて表示が切り替わります。

### スマートフォンでの操作

- リモートとローカルは、読みやすい幅で上下に並びます。画面下の「リモート」「ローカル」でそれぞれのカードへ移動できます。
- 画面下の「操作する」から操作メニューを開きます。
- 操作を選ぶと、下のナビゲーションバーは隠れます。実行・キャンセルすると再表示します。
- 操作中の選択欄をタップするとパネルが小さくなり、画面上のリポジトリやブランチを選択できます。
- 編集・コミット・ブランチ作成・フォーク・PRでは、対象を選んでから「内容を入力する」で入力画面へ進みます。ステージではファイルを選択します。
- フォーク先と元のリポジトリは、上部のタブで切り替えられます。

スマートフォンに `git-atelier.html` を転送し、JavaScriptを実行できるブラウザで開いてください。端末のファイルプレビューでは操作が動かない場合があります。

編集用の `index.html` も直接開けます。こちらは同じフォルダの `styles.css`、`git-engine.js`、`app.js` を読み込みます。オンラインの場合はGoogle Fontsを利用します。

## 最初に試すこと

最初に、プロジェクトがある場所を選びます。ここではサンプルのプロジェクトを使って操作を体験します。

- **自分のPCにあるプロジェクトから**：Git未初期化のファイルから始まります。Git初期化（`git init`）→ ファイルの編集 → ステージ（`git add`）→ 初回コミット → 空のGitHubリポジトリ作成 → 接続先の設定（`git remote add origin`）→ ブランチ公開（`git push -u`）を順番に案内します。
- **GitHubにあるプロジェクトから**：GitHub上にだけ履歴がある状態から始まります。最初にクローン（`git clone`）を行い、手元のローカルを作ります。

開始に必要な準備が終わると、自由に操作できます。準備中にページを閉じても、次回は必要な操作から再開します。「開始地点を選び直す」では、これまでのタブを残して別の開始パターンを試せます。

以前のバージョンで保存した作業は、開始地点を選び直しても元のタブに残ります。「はじめから」は、全体をリセットして開始地点の選択へ戻ります。

ポップアップの選択欄をクリックすると、その欄のリポジトリやブランチを選び直せます。画面上のブランチやリポジトリ本体を押して指定してください。丸いコミットを押すと、その時点のファイルと親コミットを確認できます。

ブランチを選択するだけではチェックアウトしません。作業中のブランチは **HEAD** と表示されます。

## 使える操作

ファイル編集、ステージ、コミット、Git初期化、空のGitHubリポジトリ作成、origin設定、プッシュ、プル、フェッチ、シンク、マージ、ブランチ作成、チェックアウト、ブランチ公開、ブランチ削除、クローン、フォーク、プルリクエスト作成・マージ、共同編集者による更新。

- **ファイルを編集**：ファイル名と内容を指定し、作業フォルダに保存します。保存だけではステージやコミットは変わりません。
- **ステージ**：変更のあるファイルをチェックボックスで選びます。選んだ時点の内容をステージに記録します。
- **コミット**：メッセージを入力し、ステージ済みの内容だけを記録します。ステージに変更がない場合は実行できません。
- ステージした後でファイルを編集すると、ステージ時点の内容と新しい編集が別々に残ります。再びステージするかどうかで、次のコミットの内容を選べます。

- **フォーク**：新しいリモートを作り、画面内の新しいタブに切り替えます。元の作業は元のタブに残ります。続けてクローンできます。
- **PR**：フォーク先でブランチ作成 → 編集 → ステージ → コミット → 公開。公開したリモートブランチを選んだら、上部の元のタブへ切り替え、リモート `main` を選びます。PRカードからマージできます。
- **クローン単体の練習**：ヘッダーの「?」→「クローンの練習」。空のローカルを持つタブを追加します。
- **リモート側の更新**：「共同編集者が更新」でリモートブランチを選ぶと、別の人によるコミットを再現できます。
- **競合**：同じファイルを別々に編集してプル／マージすると、取り込む内容を選ぶ画面を表示します。
- **操作ログ／1つ戻す／やり直す**：操作の意味とコマンド例を確認でき、変更を戻せます。

状態はこのブラウザに自動保存します。ファイルを直接開く場合の保存可否はブラウザ設定に依存し、保存できない場合は画面に表示します。操作を戻す履歴は、ページを閉じるまで保持します。「はじめから」で初期状態に戻せます。

## モデルの範囲

実際のGitやGitHubには接続せず、実際のファイルやリポジトリも変更しません。コミットの親子関係、ブランチ参照、リモート追跡参照、fast-forward、マージコミット、pushの拒否をブラウザ内で再現します。

作業フォルダ・ステージ・コミットはそれぞれ別の状態として管理します。ステージはファイル単位です。競合もファイル単位で判定し、片方の内容を選んで解決します。pullはfetch + merge、syncはpull + pushで固定しています。rebase、認証、権限、ネットワーク障害、行単位のステージは扱いません。未コミットの変更がある場合、ブランチの切り替えと統合は中止し、編集内容を保護します。PRマージはfast-forward可能なら参照を進め、分岐していればマージコミットを作ります。

## 開発・確認

Node.js 20以降で、ローカルサーバーを使う場合：

```sh
npm start
```

`http://127.0.0.1:5173` を開きます。サーバーはこのPC内からのみアクセスできます。

同じLANのスマートフォンから開く場合は、次のコマンドで起動します。

```sh
npm run start:lan
```

表示された `LAN: http://...:5173/git-atelier.html` をスマートフォンで開いてください。特定のネットワークだけで待ち受ける場合は `node server.js --host=192.168.0.40` のように、このPCのLANアドレスを指定できます。サーバーを起動している間、このPCからページを配信します。

```sh
npm test              # コミット・ブランチ操作のテスト（追加依存なし）
npm install           # ブラウザテスト用の開発依存を追加
npm run test:browser  # インストール済みEdgeを使った画面テスト
npm run build         # 編集用ファイルから配布用HTMLを再生成
```

配布用HTMLを更新するときは `npm run build` を実行してください。`git-atelier.html` への直接編集は再生成時に上書きされます。
